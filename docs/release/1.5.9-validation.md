## Visual and performance evidence

Actual Flutter widget captures are in `hyzen_flutter/qa/reference/after/` and prior
Home/Progress fixtures in `hyzen_flutter/qa/daily-rhythm/before/`. Browser captures
use the clearly labeled sample-data Flutter build. Browser Home/Streak/Calendar
opened without JavaScript exceptions, and the Calendar Add/Save flow produced a
visible event card. Calendar/Streak/Progress were checked at 320/360/390/430/800dp
and normal/200% text; existing maximum app display-scale tests remain enabled.

The initial native PixelCopy capture could retain the previous raster frame on
SwiftShader. The harness now switches capture to fullyLive frame scheduling,
settles transitions, waits for raster completion and rejects consecutive identical
captures. This affects evidence capture, not the production APK.

Full timing data and its frame counts/p90 timings/jank counts are attached to the
review release as `frame-timings.json` and `profile-summary.md`. The software GPU
exceeded the 16.7 ms raster budget; these results do not establish physical-device
60 FPS. Physical Infinix Note 8 GPU, camera/OCR, live Drive, notification delivery
and sustained memory/battery testing remain pending.

## Cloud rollout remains blocked

The new wallet/calendar worker and additive D1 migration are implemented and
bundled, but **production deployment has not happened**. Existing Cloudflare login
is unavailable in this environment. Repository secret `CLOUDFLARE_API_TOKEN` and
repository variable `CLOUDFLARE_ACCOUNT_ID` are needed by the reviewed deployment
workflow. No production secret, OneSignal setting or Firestore policy was changed.

Private study history and local calendar/reminder persistence continue to work.
The new online wallet, cross-device calendar and fifteen-second board cache policy
must not be described as deployed until that worker rollout and an authenticated
production check pass. HTTP fixture tests use test keys and an isolated database.
The APK is a **prerelease review build**, excluded from the stable updater target.

Corrected capture/measurement run completed successfully. The release package
contains refreshed native screenshots and timing data from that run; the APK
checksum is unchanged.
